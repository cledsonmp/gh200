Gerenciamento de espaço/armazenamento



Vamos destrinchar isso com um exemplo prático do dia a dia de um desenvolvedor para ficar bem visual.

Imagine que o seu projeto no GitHub Actions rodou um build hoje e gerou três coisas principais:

  1. O Histórico (Run): O registro que diz: "O workflow CI Pipeline rodou hoje às 14h, foi disparado por um push na branch main e terminou com sucesso."

  2. Os Logs: O textão com todas as linhas que apareceram na tela preta (ex: npm install baixando pacotes..., compilando arquivos..., testes finalizados com sucesso).

  3. O Artefato: Um arquivo compactado chamado relatorio-de-cobertura.zip que tem 50 Megabytes de relatórios de testes.

O Problema: O Armazenamento Está Lotando

O espaço do seu repositório está quase no limite por causa de arquivos acumulados. Você decide escrever um script usando a API REST do GitHub para fazer uma faxina, mas cada "gaveta" exige um comando diferente. Veja o que acontece em cada escolha:

Cenário 1: Você quer apagar apenas o arquivo pesado, mantendo o histórico

Se você quer economizar espaço rápido apagando só o arquivo .zip, mas quer manter o registro de que o build aconteceu e os logs para auditoria, você usa o endpoint de artefatos:

  • Comando: DELETE /repos/MINHA-ORG/MEU-REPO/actions/artifacts/12345 (onde 12345 é o ID daquele .zip).

  • O resultado: O arquivo relatorio-de-cobertura.zipsome e o espaço é liberado. Porém, se você entrar no GitHub, o histórico do workflow (run) continua lá bonitinho, com o status de sucesso e os logs intactos. É uma cirurgia precisa.

Cenário 2: Você quer apagar apenas o textão dos logs

Se o seu problema não é espaço de arquivos, mas você quer limpar os registros de texto de uma rodada específica por privacidade:

  • Comando: DELETE /repos/MINHA-ORG/MEU-REPO/actions/runs/67890/logs

  • O resultado: Os textos da tela preta somem, mas o artefato e o registro geral de que a execução ocorreu continuam lá.

Cenário 3: Você quer deletar a execução inteira (Run)

Se você decidir apagar o registro completo da rodada:

  • Comando: DELETE /repos/MINHA-ORG/MEU-REPO/actions/runs/67890

  • O resultado: Aqui é "tudo ou nada". O histórico principal da rodada é apagado, arrastando junto os logs e qualquer vínculo com os artefatos daquela execução.

E se em vez de apagar manualmente, eu quiser mudar a regra geral?

Digamos que você não quer ficar rodando scripts de DELETE todo dia. Você quer que o próprio GitHub apague os arquivos automaticamente após 7 dias para sempre.

Para mudar essa regra/política global (e não apagar um arquivo individual agora), você não usa DELETE. Você usa o método PUT para atualizar as configurações de permissão e retenção da organização ou do repositório:

  • Comando: PUT /repos/MINHA-ORG/MEU-REPO/actions/permissions/artifact-and-log-retention passando no corpo da requisição que o limite de dias (days) agora é 7.

Precisamos saber escolher a "gaveta" certa !
