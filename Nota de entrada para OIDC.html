Concentre a revisão nestes pontos:

Ponto

O que você deve saber

Objetivo do OIDC

Autenticar na nuvem sem guardar uma credencial permanente de acesso.

id-token: write

Permite solicitar o JWT OIDC; não concede permissão para alterar recursos na nuvem.

Fluxo de autenticação

GitHub emite JWT → provedor valida a confiança → fornece token temporário.

Claims

iss: emissor; aud: destinatário; sub: identidade/contexto autorizado.

Confiança federada

Restringe quais repositórios e contextos podem autenticar. Branch e environment podem mudar o sub.

Autenticação × autorização

Login pode funcionar e o deploy falhar por falta de permissões, como Azure RBAC.

Leitura do workflow

Identificar permissões, action de login, inputs e uso de secrets.



Para o exemplo Azure, entenda que azure/login faz a troca e que Client ID, Tenant ID e Subscription ID identificam a configuração. Eles não são um client secret.

Deixe em segundo plano a memorização dos caminhos do portal, todos os cliques, comandos administrativos e o script Python para inspecionar JWT. Eles ajudam na prática, mas não precisam ser seu centro de revisão.

Minha sugestão: domine esses sete pontos, refaça o simulado e use o manual para uma execução prática quando puder. Essa é uma prioridade de estudo, não uma garantia sobre quais perguntas aparecerão no exame.
