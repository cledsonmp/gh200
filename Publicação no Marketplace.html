Os Pilares Teóricos da Publicação no Marketplace



Para que uma Action desenvolvida por você saia do seu repositório privado ou público e passe a ficar disponível para a comunidade no Marketplace do GitHub, o processo exige o cumprimento de passos administrativos e de segurança bem específicos definidos pela plataforma:

PNG

  1. Repositório Público e Metadados Corretos: O repositório precisa ser público e conter obrigatoriamente o ficheiro de metadados (action.yml ou action.yaml) na raiz, preenchido corretamente com nome, descrição, ícone e cor (usados na vitrine do Marketplace).

  2. Criação de uma Release com Tag (Semantic Versioning): O GitHub Marketplace está diretamente atrelado ao sistema de Releases e Git Tags (ex: v1.0.0). A publicação de uma action não acontece de forma automática por comandos de upload ou issues; ela é oficialmente disparada quando você cria uma nova release no repositório.

    PNG

  3. A Caixa de Seleção (Publish this Action to the GitHub Marketplace): Ao preencher os dados para criar a release no painel do GitHub, existe uma caixa de seleção específica para marcar se você deseja listar aquela action no Marketplace. Se houver algum erro nos metadados do seu action.yml, o GitHub exibirá um alerta nessa mesma tela impedindo a marcação até que seja corrigido.

    PNG

  4. Requisitos de Segurança Obrigatórios (2FA): Como medida de segurança contra sequestro de contas e injeção de código malicioso em cadeias de suprimentos (supply chain attacks), o autor é obrigado a ter a Autenticação de Dois Fatores (2FA) ativa na sua conta do GitHub para conseguir publicar qualquer item no Marketplace.

    PNG

  5. O Mito da "Certificação" (Cuidado com pegadinhas de prova!): Um detalhe muito cobrado em exames é que o facto de uma action estar listada no Marketplace NÃO significa que ela foi revisada, testada ou certificada pelo GitHub em termos de segurança. A listagem é aberta aos autores desde que atendam aos requisitos formais, cabendo aos utilizadores avaliar a confiabilidade do código de terceiros.

Se a sua action for utilizada apenas de forma interna (dentro do seu próprio repositório ou de outros repositórios privados da sua organização via referência direta por URL do Git, como uses: seu-usuario/seu-repo/.github/actions/minha-action@main), a secção de branding (com o ícone e a cor) é totalmente opcional.

No entanto, se você tentar marcar a caixa de publicação para o GitHub Marketplace ao criar uma release, o GitHub valida os metadados do seu ficheiro action.yml e rejeita a publicação caso o branding (com icon e color) esteja em falta.
