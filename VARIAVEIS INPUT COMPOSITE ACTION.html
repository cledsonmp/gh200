Guia Técnico Comparativo: Composite Actions vs. JavaScript Actions no GitHub Actions

1. O Problema Fundamental de Escopo

No ecossistema do GitHub Actions, a forma como os parâmetros informados pelo consumidor no bloco with: são repassados para dentro da execução varia drasticamente dependendo do tipo de Action criado. Compreender essa distinção evita falhas críticas de escopo e variáveis vazias em pipelines.


2. Composite Actions (`using: "composite"`)

As Ações Compostas executam blocos de passos em sequência (como comandos Bash). O motor do GitHub NÃO injeta automaticamente variáveis INPUT_ no ambiente por padrão. É exigido o uso do contexto inputs e um mapeamento explícito no nível do step.

3. JavaScript Actions (`using: 'node...'`)

Nas ações escritas em Node.js, o ambiente processa os inputs de forma nativa e automática por meio do pacote oficial @actions/core, convertendo diretamente os parâmetros definidos no arquivo de metadados sem necessidade de mapeamentos manuais em variáveis de ambiente.
