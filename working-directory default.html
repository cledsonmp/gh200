Imagine que o seu projeto tem uma estrutura onde o código-fonte ou a aplicação Node.js está guardada dentro de uma pasta específica chamada backend, e você quer que todos os comandos run executem lá dentro por defeito.

YAML

name: Exemplo de Working Directory Padrão


on: [push]

jobs:
  construir:
    runs-on: ubuntu-latest
    
    # Definimos aqui o diretório padrão para todos os steps 'run' deste job
    defaults:
      run:
        working-directory: ./backend

    steps:
      - name: Checkout do código
        uses: actions/checkout@v4
        # Nota: O checkout continua a ser feito na raiz do repositório por defeito

      - name: Instalar dependências
        run: npm install
        # Como definimos o defaults.run, este comando vai correr automaticamente dentro de './backend'

      - name: Executar testes
        run: npm test
        # Este step também correrá dentro de './backend' sem precisar de repetir o caminho

Detalhes Importantes para a Prova:

  • Escopo: O bloco defaults.run pode ser definido tanto a nível global (para o workflow inteiro, antes dos jobs) quanto a nível individual (dentro de um job específico).

  • Sobrescrita (Override): Se por acaso precisar que um step específico corra noutro sítio, cada step run individual ainda pode declarar o seu próprio working-directory para ignorar o padrão definido.

  • Restrição: Esta diretiva aplica-se exclusivamente a passos do tipo run (comandos de terminal), não afetando a execução de actions de terceiros (como o actions/checkout).
